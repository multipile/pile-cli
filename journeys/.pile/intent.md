The sessions somebody really has with `pile`, told as scripts that run the
built binary and hold it to what each command's help claims.

A journey belongs here when it is one session a person or an agent could
have: a repository they could arrive at, the commands they would type, and
what they need to be told. What one command does with one input belongs in
the suite beside the commands, not here. A journey judges only what `pile`
prints and what git holds, never how `pile` is built inside. A recording of
a journey is of one run of one checkout, and is not kept.

Read this pile to find out what a session with `pile` is promised to look
like, and how to watch one. Change it in the commit that changes what a user
of `pile` sees.
